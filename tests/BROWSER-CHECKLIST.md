# 真浏览器验证清单

> **改任何界面之前，先读工作区根目录的 [`设计偏好.md`](../../../设计偏好.md)** ——
> 那是用户的通用诉求（省空间优先、同一件事一套说法、布局要写死意图、状态靠颜色…）
> 与本项目踩过的坑（规格会过时、改字段顺序要移动不能复制、CSS 覆盖会被同权重吃掉、
> 新红线必须反向验一次…）。用户表述不清时按那份判断，不要按字面或规格原文判断。
> 完整路径：`D:\harness\浏览器插件\设计偏好.md`
>
> **两条路，优先走第一条**：
> 1. **自动化（推荐）**：`cd _e2e && npm i && node run.js` —— 用 **≤136 的 Chromium**（**不是**系统 Edge；环境前置见下面 §0.1）加载未打包扩展跑装置页面，
>    **128 项断言 = 内容层 73 + UI 层 55**（**引用 round 18 实测**，全绿）+ 截图，见 `tests/E2E-REPORT.md`。改完代码重跑它即可。
> 2. **人工复核**：下面这份清单，用于自动化覆盖不到或需要"肉眼判断观感"的项。
>
> `node tests/run.js` 覆盖的是**纯逻辑**（匹配、裁决、字段往返、抓取解析、Markdown）。
> 本清单里那些依赖**真实布局/几何/浏览器 API/视觉观感**的项，Node 垫片测不了，必须真浏览器确认。

## 0. 准备

1. 解压 `dist/keyword-highlighter-v<version>.zip`，覆盖扩展所在文件夹。
2. `chrome://extensions` → 开发者模式 → 点该扩展的 **⟳ 重新加载**。
3. 打开控制台，确认没有红色报错（`[KH]` 前缀为插件日志）。

> 注入测试配置时务必带 `pageRebuildSilentMs:0, pageRebuildGapMs:0`，
> 否则默认有 1s 静默 + 2s 节流，短时间内读到的仍是旧状态（会误判为 bug）。
> 就绪状态可看 `<html data-kh-state="on|off">`（`on` = 已进入高亮态）。

### 0.1 真机回归环境（≤136 Chromium · `KHE_BROWSER` · 语言包前置）

> 上面第 1 条那条「自动化」的路（`_e2e/run.js`）有**三个前置**。少一个，回归一定红，
> 而且**红的样子像产品 bug**——先核对这里，再决定要不要开 issue。

**① 浏览器必须是 ≤136 的 Chromium 系（硬要求）**

- 装置靠 `--load-extension=<扩展目录>` 加载未打包扩展（`_e2e/harness.js` 的 `launch`），

  `扩展的 service worker 没起来：找不到 background/service-worker.js`，并列出实际浏览器路径与
  当前 SW 列表（`_e2e/harness.js:68-88`）。**2026-10-05 之前**的现象更迷惑：装置抓到 Chrome 自带
  组件扩展的 SW、extId 变成别人的，然后 `net::ERR_FILE_NOT_FOUND at chrome-extension://…/options/options.html`
  ——两种都**不是**扩展坏了。**实测 154.0.8037.98 加 `--enable-unsafe-extension-debugging` 也救不回来**
  （`node _e2e/probe-sw-urls.js --enable-unsafe-extension-debugging` 复现）。

## 1. 高亮纯视觉 / 不改 DOM（最高优先级）

**为什么必须真浏览器**：`CSS.highlights` 与 `::highlight` 只有浏览器实现；孤儿文本节点问题也只在框架真实写值时暴露。

- [ ] 普通词命中后，DevTools 里**搜不到**插件生成的 `<span class="kh-highlight">`；
      页面 DOM 中**没有任何** `data-kh-*` 属性。
- [ ] `CSS.highlights` 里能看到 `kh-hl-*` 条目（控制台执行 `[...CSS.highlights.keys()]`）。
- [ ] 表格页：命中普通词 → **翻页** → 新内容正常写入页面、无残留高亮、旧词不高亮。
- [ ] 表格页：命中普通词 → 用 `td.textContent = '新值'` 改单元格 → 高亮正确刷新（characterData 生效）。
- [ ] 同上但用 `td.childNodes[0].nodeValue = '新值'`（原地改值）→ 同样刷新。
- [ ] 在控制台执行：`document.querySelectorAll('.kh-highlight,[data-kh-highlighted]').length === 0`。

## 3. 抓取后续字段（多行内容，附录A §8）

**为什么必须真浏览器**：视觉行提取依赖 `getBoundingClientRect().top`，合并块依赖真实 `rowSpan/colSpan`。

- [ ] 抓一个**多行**字段（如「驳回原因 / 审核结果描述」）→ 面板里**每行独立**，不折叠成一行。
- [ ] 右格是 flex 并排的多段内容（如「是 高价值」）→ 合并成**一行**，不被误拆成多行。
- [ ] 标签格 `rowspan` 合并多行、右侧内容纵向延伸超过合并范围 → **超出部分也能抓到**。
- [ ] 层级内容（基本信息 / 测试信息 / 资质信息 / 运营备注）→ 按**多行表格**带层次展示。
- [ ] **列对齐（K8 回归项，必看）**：多行表格必须是 `[字段 label][二级标题][内容]` 三列网格 ——
      字段 label 只在首行出现并**纵向合并**（左侧不留一串空方格）；
      「驳回字段：X」与它下面的**理由**必须落在**同一列**（不能把理由挤到最右侧独立一列）；
      版本 B 这类含 `32位包:` / `64位包:` 的样例，包分组标题要**跨列覆盖**下方子项、右缘与子项齐平。

- [ ] **着色（K9 回归项，必看）**：抓取表格**没有表头行**，只有左边的「字段 label」格（如 `审测一体审核结果描述`
      / `驳回原因`）该上淡底色；`基本信息` / `测试信息` / `资质信息` / `运营备注` / `驳回字段：X` / `32位包:` / `64位包:`

- [ ] **复制**面板里的表格内容 → 换行与结构能还原。

## 8. 站点规则 / 快捷键 / 更新

- [ ] 黑名单：加入某域名 → 该站不高亮，其它站正常。
- [ ] 白名单：加入某域名 → **只有**该站高亮。
- [ ] **白名单即时生效（K40）**：在设置页新增一条白名单后，**不刷新**其它已开着的网站页面 →
      那些页面的高亮应立刻消失（旧实现只重编译不重评站点门禁，会继续高亮）。
- [ ] **「禁用本站」即时生效（K40）**：在弹窗点 `🚫 禁用本站` → 当前页高亮立刻消失，
      且**不刷新**页面也保持失效；再点 `✅ 启用本站` → 高亮立刻回来。
      多试几次（旧实现与 storage 通知存在竞态，表现为"时灵时不灵"）。
- [ ] 网址级规则（scope=url，前缀/正则）：同一站不同分页可分别生效/失效。
- [ ] URL 变化（SPA 路由）→ **重新评估站点规则**：切到被禁用的分页 → 高亮被收掉、无残留。
- [ ] **SPA 列表 → 详情**（K41）：点列表项进详情页（内容异步渲染）→ 详情页的关键词**必须自己高亮**，
      不需要刷新；且**当前页本来不生效**时也要能恢复（如网址级白名单只放行详情 URL、或本页被临时禁用）——
      这是用户实测缺陷（"点进去一个都不亮、刷新就好"）的复现路径。
- [ ] 诊断口诀：**切一下标签页再切回来**。若详情页这时出现高亮 → 说明"缺的只是一次重建"
      （K41 已修路由通道；若仍不复现，考虑自定义元素晚挂 ShadowRoot 那条未修路径）。
- [ ] **后退/前进缓存（bfcache，K43）**：A 页 → 点进 B 页 → 点浏览器**后退**回到 A 页 →
      A 页的高亮必须还在（不得需要刷新）。同理前进到 B 也要有。
      （`_e2e` 组 17 用合成 `PageTransitionEvent` 覆盖：进缓存不下线 / 真卸载才下线 / 恢复必须重新上线。）
- [ ] `Ctrl+Shift+H` 切全局；`Ctrl+Shift+S` 切本站禁用；`Ctrl+Shift+O` 打开设置。
- [ ] 全局暂停时扩展图标变灰（`icon*-paused.png`）。
- [ ] 「检查更新」能拉到 `update.xml` 版本（网络可达时）。
