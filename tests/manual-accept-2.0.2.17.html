⑤ bug：仅抓取模式 + 图片命中词，以前一次 OCR 都不发

根因（一句话）

编译层 src/core/compiler.js 的 ocrMeta() 原本是
imgOcr: !!(kw && kw.imgOcr) && !o.fetchOnly —— 仅抓取词 fetchOnly=true，把用户勾的「识别图片文字」直接抹成 false；
于是 src/features/img-ocr.js 的 anchorsFor() 第 1 条准入 if (!rule.meta.imgOcr) return; 永远拦住 ⇒ 条目 0 条、一次识别都不发。2.0.2.17 去掉了那个短路（图片命中词判的是 OCR 出来的文字，与核心词无关）。

怎么点

  • 本节的「实测」是页面真的跑了链路：真实 Compiler.ocrMeta() 编译出 meta → 真实 KH.ImgOcr.build() 从本页下方那张真实表格的截图值格里取图 → 建出条目。
  • 真机复现：仅抓取词 + 配「抓取后续字段」（含 截图#图）+ 图片命中词，图片分区这次真的会动。
判据：ocrMeta({imgOcr:true}).imgOcr === true（旧版是 false）；ImgOcr.build() 后存在 ruleId 等于本夹具规则的条目（旧版 0 条）。
